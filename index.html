Acceleration of nonlinear functions for Edge-AI processors

We design Verilog units for ReLU, Sigmoid, Tanh and Softmax, attach them to a small processor as custom instructions, and show on an FPGA that a real Edge-AI demo runs faster with little loss of accuracy.

          Reference

          Core concepts

          Activation functions run after every layer, and most need exponentials and division. On a small integer core with no FPU, that is where inference stalls. The engineering is a three-way trade: accuracy, area and speed.

          Fixed-point arithmetic

          A Qm.n number is an integer read with n fractional bits. 16-bit Q4.12 covers about −8 to +8 with a step of 1/4096 ≈ 0.00024.

          • Multiplying two Qm.n values gives 2n fractional bits; shift right by n afterwards and choose truncate or round.
          • Overflow must saturate (clip), not wrap, or a large activation flips sign.
          • Match the model's format. Many TinyML models use int8 with a scale factor; confirm early.

          Shortcuts each function allows

          • ReLU: check the sign bit and output x or 0. A mux, zero error.
          • Sigmoid is symmetric, σ(−x) = 1 − σ(x): build the positive half and mirror it. Beyond |x| ≈ 8 the output is within 0.0004 of 0 or 1.
          • Tanh is a scaled sigmoid, tanh(x) = 2σ(2x) − 1. One unit can serve both.
          • Softmax: subtract the maximum first so every ex lies in (0, 1], then one reciprocal of the sum and one multiply per element.
          softmax(xi) = exi − xmax / Σj exj − xmax

          Approximation techniques

          Piecewise linearSlope and offset per segment: y = a·x + bOne multiplier (often a DSP) + small table1–2 cyclesSigmoid/Tanh at 16 bits
          PLANPiecewise linear with power-of-two slopesShifts and adds, no multiplier1 cycleSmallest area; max error ≈ 1.9%
          Polynomiala·x² + b·x + c, often per segmentTwo multipliers, or one reused2–3 cyclesThe exponential in Softmax
          CORDICIterative shift-add rotations (hyperbolic mode)Adders and shifters only≈1 cycle per bitWhen DSPs are scarce

          The classic PLAN sigmoid (Amin et al., 1997) uses segments at |x| < 1, 1–2.375, 2.375–5 and ≥ 5, with slopes 1/4, 1/8, 1/32 and 0. It is the curve in the chart at the top and a good first Verilog exercise.

          For Softmax's exponential, I-BERT writes the input as a multiple of ln 2 plus a small remainder, so ex = 2−z × ep. The 2−z part is a right shift; ep needs only a 2nd-order polynomial on (−ln 2, 0].

          Test every unit against a double-precision reference over every input. For 16-bit inputs that is 65,536 values. Report max and mean error per function, then end-to-end classification accuracy.

          Reference

          Processor integration

          Each unit becomes a new instruction. The decoder recognizes a reserved opcode, routes two register values to our unit instead of the ALU, and writes the result back. Fetch, registers and writeback stay as they are.

          Instruction encoding

          RISC-V reserves custom-0 (opcode 0001011) and custom-1 (0101011) for designers, so new instructions keep the core standard-compliant. R-type: rs1 and rs2 in, rd out, funct3/funct7 pick the function. A possible map:

          funct3InstructionOperation
          000act.relu rd, rs1max(0, rs1)
          001act.sig rd, rs1σ(rs1)
          010act.tanh rd, rs1tanh(rs1)
          011act.exp rd, rs1ers1 for rs1 ≤ 0 (Softmax step)
          100act.recip rd, rs11 / rs1 (Softmax normalization)

          If the supervisor's processor is not RISC-V, the same idea applies: find unused opcodes and extend the decoder.

          • Tightly coupled: the unit sits beside the ALU. Lowest overhead; right for ReLU, Sigmoid, Tanh. A multi-cycle unit must stall the pipeline.
          • Memory-mapped: a bus peripheral the CPU writes and reads. More overhead per value, but it can hold a whole vector, which suits Softmax.
          • Middle path for Softmax: a few custom instructions plus a small internal state (running max and running sum).

          Software side

          The compiler does not know our instructions. The GNU assembler's .insn directive emits them from inline assembly. Wrap each in a C function with a plain C fallback chosen by a flag, so the same model code builds both ways for a fair comparison.

          static inline int32_t act_sig(int32_t x) {
#ifdef USE_HW_ACT
    int32_t y;
    asm volatile (".insn r 0x0B, 1, 0, %0, %1, x0" : "=r"(y) : "r"(x));
    return y;
#else
    return sigmoid_q12_sw(x);   /* reference C version */
#endif
}

          Which processor? Ask first: the supervisor's 2023 NEWCAS paper describes his own small modular RISC processor built for custom-instruction extensions. Open-source options built for this: NEORV32 (Custom Functions Unit), PicoRV32 (coprocessor interface), and VexRiscv inside CFU Playground.

          The main deliverable is a trade-off study: for each function, which technique gives the best balance of area, speed and accuracy. One chart of error vs. LUT count per design will carry most of the final report.
